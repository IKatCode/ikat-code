## Установка

macOS и Linux:

```sh
curl -fsSL https://github.com/IKatCode/ikat-code/releases/latest/download/install.sh | sh
```

Windows:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://github.com/IKatCode/ikat-code/releases/latest/download/install.ps1 | iex"
```

Потом откройте новый терминал и запустите его в проекте:

```sh
cd ваш-проект
ikat
```

В первый раз IKat спросит, какую модель использовать.

<details>
<summary>Системы, требования, что делает установщик</summary>

<br>

Сборки есть для macOS (Apple Silicon и Intel), Linux (x64 и arm64, glibc и musl) и Windows (x64 и
arm64).

- Windows: команды IKat выполняет в Git Bash, нужен
  [Git for Windows](https://git-scm.com/download/win). `ssh-keygen`, который нужен установщику,
  в Windows 10 и 11 уже есть.
- Alpine и другие системы на musl: сначала `apk add libstdc++ libgcc`.

Установщик скачивает сборку для вашей системы, сверяет её с контрольными суммами релиза и их
подписью и кладёт `ikat` вместе с `rg` (ripgrep) в `~/.ikat/bin` или, на Windows, в
`%LOCALAPPDATA%\ikat\bin`. Потом добавляет эту папку в PATH. Можно и вручную: взять архив на
[странице релизов](https://github.com/IKatCode/ikat-code/releases) и распаковать куда угодно.

</details>

## Что он умеет

- Работает на модели, которую выберете вы: ключ OpenAI или OpenRouter, любой OpenAI-совместимый
  API (DeepSeek, Qwen, шлюз компании, локальный сервер), ключи Anthropic и Google или подписка
  ChatGPT. `/model` меняет модель посреди разговора.
- Читает проект, меняет код, запускает ваши тесты и линтеры и рассказывает, что изменил и как это
  проверил.
- Спрашивает, прежде чем выполнить команду или изменить файл, если вы не скажете иначе. Любое
  изменение можно откатить через `/rewind`.
- На macOS и Linux держит команды в песочнице.
- Работает без интерфейса в скриптах и CI, с выводом в JSON.
- Говорит по-русски и по-английски.

## Модели

| Что у вас есть | Как подключить |
|---|---|
| Ключ OpenAI или OpenRouter | `ikat login openai` или `ikat login openrouter`, либо `OPENAI_API_KEY` / `OPENROUTER_API_KEY` |
| Любой другой OpenAI-совместимый API | раздел `providers` в `~/.ikat/settings.json`, пример ниже |
| Подписка ChatGPT Plus или Pro | `ikat login` и вход в браузере |
| Ключ Anthropic или Google | `ikat login anthropic`, `ikat login google` или `ANTHROPIC_API_KEY` / `GEMINI_API_KEY` |
| Ollama, LM Studio, llama.cpp, vLLM | `ikat --model ollama/qwen3-coder:30b`; локальный сервер находится сам |

Любая модель OpenRouter — это один флаг:

```sh
ikat --model openrouter/qwen/qwen3-coder
```

Любой другой OpenAI-совместимый API, например собственный адрес провайдера или шлюз компании:

```json
{
  "providers": {
    "corp": {
      "baseUrl": "https://llm.corp.example/v1",
      "apiKeyEnv": "CORP_LLM_KEY",
      "models": { "coder-xl": { "contextWindow": 200000 } }
    }
  }
}
```

```sh
ikat --model corp/coder-xl
```

Ключ берётся из переменной, названной в `apiKeyEnv`, или из `ikat login corp` — тогда он хранится в
системном хранилище ключей. Локальной модели нужна поддержка вызова инструментов; если сервер не
сообщает размер контекста, IKat считает его равным 32 768 токенам, а настоящий задаётся через
`contextWindow`. Что подключено, показывает `ikat doctor`.

Настройки самого проекта (`.ikat/settings.json`) провайдеров не добавляют и не меняют:
склонированный репозиторий не решает, куда уходит ваш код.

## Работа

Опишите задачу так, как объяснили бы коллеге:

```
Итог корзины не учитывает скидки на наборы. Разберись почему и исправь.
```

| Клавиша или команда | Что делает |
|---|---|
| `Esc` | остановить текущий шаг |
| `Esc Esc`, `/rewind` | вернуться к одной из прошлых точек, с файлами и разговором |
| `ikat -c`, `ikat -r` | продолжить последний разговор в этой папке или выбрать более старый |
| `/init` | записать `IKAT.md`: как собрать и проверить проект; IKat читает его при каждом запуске |
| `/model` | сменить модель |
| `/` и `?` | все команды и все клавиши |

## Права

Перед командой или изменением файла IKat показывает, что собирается сделать и насколько это
рискованно. Можно разрешить один раз, разрешить такие команды в этом проекте насовсем или
отказать и сказать, что делать вместо этого.

![IKat спрашивает, можно ли выполнить git status: уровень риска и варианты ответа](docs/ask.svg)

| Режим | О чём спрашивает |
|---|---|
| `default` | спрашивает о командах и изменениях файлов |
| `accept-edits` | меняет файлы проекта без вопросов, о командах спрашивает |
| `plan` | составляет план и ждёт вашего «да», прежде чем что-то менять |
| `auto` | как `accept-edits`, и ещё без вопросов выполняет команды, не выходящие из песочницы (macOS, Linux) |
| `readonly` | только читает: ничего не пишет и не запускает |
| `bypass-permissions` | ничего не спрашивает |

`Shift+Tab` переключает первые три. Любой режим задаётся через `/mode <имя>` или
`ikat --permission-mode <имя>`.

<details>
<summary>Работа совсем без вопросов</summary>

<br>

```sh
ikat --permission-mode bypass-permissions
```

Или `/mode bypass-permissions` в открытой сессии. Чтобы всегда запускаться в этом режиме, добавьте
в `~/.ikat/settings.json`:

```json
{ "permissions": { "defaultMode": "bypass-permissions" } }
```

Режим работает на любой системе, в том числе на Windows. `Shift+Tab` в него не переключает, а
настройки проекта не могут его включить. Ваши запрещающие правила и защита секретов (файлы `.env`,
`~/.ssh`, ключи облаков) продолжают действовать, всё остальное выполняется. На macOS и Linux
команды по-прежнему запускаются в песочнице, но если команде нужно из неё выйти, её выпустят без
вопроса. На Windows песочницы нет, и команда может всё, что можете вы. Включайте этот режим в
контейнере, в виртуальной машине или в копии проекта, которую не жалко.

</details>

<details>
<summary>Песочница</summary>

<br>

На macOS и Linux команды, которые запускает IKat, могут писать только в папку проекта и во
временную папку, а сети у них нет, если вы не открыли её в настройках для нужных адресов. Что-то
вроде `npm install` сначала спросит и выполнится вне песочницы. На Windows песочницы пока нет;
если она нужна, запускайте IKat в WSL.

Настройки проекта, например команды, которые он разрешает без вопросов, начинают действовать
только после того, как вы подтвердите доверие к папке. Перед этим IKat показывает, что в них.

</details>

## Скрипты и CI

```sh
ikat -p "Почини падающий тест в cart.test.ts" --permission-mode accept-edits --allowed-tools "Bash(npm test:*)"
```

`-p` выполняет одну задачу и завершается. Спросить он не может, поэтому всё, что требует вопроса,
отклоняется, и IKat печатает правило, которое это разрешило бы; каждому правилу — свой
`--allowed-tools`. С `--output-format json` или `stream-json` результат удобно читать другой
программе. В одноразовом контейнере CI `--permission-mode bypass-permissions` разрешает всё.

## Обновление и удаление

`ikat update` ставит последний релиз: проверяет подпись релиза и контрольную сумму, убеждается,
что новый `ikat` запускается, и только потом заменяет старый. `ikat update --check` только
сообщает, есть ли версия новее. В версиях до 0.1.3 команды `ikat update` нет: один раз запустите
команду установки ещё раз.

Раз в сутки IKat спрашивает у GitHub, какая версия последняя, и сообщает, когда вышла новая. В этом
запросе нет ничего ни о вас, ни о вашем коде. Чтобы выключить, задайте `"updates": { "check": false }`
в `~/.ikat/settings.json` или `IKAT_NO_UPDATE_CHECK=1`; в CI проверка выключена сама. С
`"updates": { "auto": true }` IKat ставит новые версии сам, и они запускаются при следующем открытии.

Чтобы удалить IKat, удалите `~/.ikat/bin` (или `%LOCALAPPDATA%\ikat\bin`) и уберите эту папку из
PATH; сессии и настройки лежат в `~/.ikat`.

## Помощь

`ikat doctor` проверяет терминал, Git, подключение к модели и настройки и говорит, что поправить.
Если не помогло, [создайте issue](https://github.com/IKatCode/ikat-code/issues) и приложите его
вывод. О проблемах безопасности сообщайте не публично, а как описано в [SECURITY.md](SECURITY.md).

## Приватность

Код и запросы уходят только выбранному вами провайдеру модели. Телеметрии в IKat нет.
